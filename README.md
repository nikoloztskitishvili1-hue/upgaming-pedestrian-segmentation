# Pedestrian Detection & Instance Segmentation (YOLOv8-seg + ONNX)

End-to-end Computer Vision project built for the **Upgaming Talent Growth Program**
(Machine Learning Engineer | Computer Vision).

The system detects pedestrians in images and segments each one at pixel level (instance segmentation).
It covers the full ML workflow: data preparation, a zero-shot baseline, three training experiments, evaluation,
ONNX optimization, error analysis and a Gradio demo.

- **Dataset:** [Penn-Fudan Pedestrian](https://www.cis.upenn.edu/~jshi/ped_html/) (~170 images), 80 % train / 20 % validation, fixed seed
- **Models:** YOLOv8n-seg and YOLOv8s-seg (Ultralytics), pretrained on COCO and fine-tuned
- **Optimization:** ONNX export compared with PyTorch on CPU (size, latency, accuracy)
- **Demo:** Gradio app (image upload, webcam snapshot, live webcam) running the ONNX model

Full write-up (problem, decisions, experiments, error analysis, limitations): [TECHNICAL_REPORT.md](TECHNICAL_REPORT.md)

## Results (validation split, 34 images)

| Model | mask mAP50-95 | box mAP50-95 | Size (MB) |
|---|---|---|---|
| zero-shot yolov8n-seg (no training) | 0.699 | 0.837 | 7.1 |
| zero-shot yolov8s-seg (no training) | 0.694 | 0.866 | 23.9 |
| exp1: yolov8n-seg fine-tuned | 0.796 | 0.831 | 7.0 |
| exp2: yolov8s-seg fine-tuned | 0.800 | 0.839 | 23.8 |
| **exp3: yolov8s-seg, backbone frozen (selected)** | **0.805** | 0.840 | 23.8 |

Fine-tuning improved the mask quality by about 0.10 mAP50-95; the three fine-tuned models are within noise of each other.

ONNX vs PyTorch on CPU: 428 ms vs 403 ms per image, 47.4 MB vs 23.8 MB, mask mAP50-95 0.792 vs 0.805 -
in this setup ONNX did **not** speed the model up (details in the report).

All tables: [`results/tables.md`](results/tables.md).

## Project structure

```
.
├── main.ipynb            # full pipeline: data -> baseline -> experiments -> evaluation -> ONNX -> analysis -> demo
├── app.py                # standalone Gradio demo
├── requirements.txt      # dependencies
├── TECHNICAL_REPORT.md   # technical report
├── models/
│   └── best.pt           # best trained PyTorch weights (exp3, selected by validation mask mAP50-95)
└── results/              # metrics, optimization table, error analysis, training curves
```

`PennFudanPed/`, `dataset/` and `experiments/` are generated by the notebook and are not stored in the repository.

## Model files

- `models/best.pt` (23.8 MB) is included in this repository.
- `best.onnx` (47.4 MB) is too large for a normal upload: download it from the
  [Releases page](https://github.com/nikoloztskitishvili1-hue/upgaming-pedestrian-segmentation/releases)
  and put it into `models/`. It can also be re-created at any time by running `main.ipynb`
  (the ONNX export section), or with `YOLO("models/best.pt").export(format="onnx", imgsz=640, simplify=True)`.

## How to run

### Option A - re-create everything on Google Colab (free GPU)

1. Open `main.ipynb` in Google Colab (`File -> Open notebook -> GitHub`, paste the repository URL).
2. `Runtime -> Change runtime type -> T4 GPU`.
3. `Runtime -> Run all`. The notebook downloads the dataset, trains three experiments (about 3-4 minutes each),
   evaluates them, exports to ONNX, writes `models/` and `results/`, and starts the Gradio demo with a public link.

### Option B - run only the demo locally (no training)

```bash
git clone https://github.com/nikoloztskitishvili1-hue/upgaming-pedestrian-segmentation.git
cd upgaming-pedestrian-segmentation
pip install -r requirements.txt
python app.py            # opens http://127.0.0.1:7860
```

`app.py` uses `models/best.onnx` if it exists and falls back to `models/best.pt` otherwise.
To force the PyTorch weights: `MODEL_PATH=models/best.pt python app.py`.
